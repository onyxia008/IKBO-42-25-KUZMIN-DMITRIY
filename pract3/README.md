# Граф зависимостей npm-пакета (вариант 17)

Учебный CLI-инструмент на Python 3 без сторонних библиотек.
Дисциплина «Конфигурационное управление», РТУ МИРЭА.

## 1. Общее описание

| Этап | Что реализовано | Тег |
|---|---|---|
| 1. Прототип | чтение параметров из JSON, вывод «ключ: значение», ошибки | `pract3-stage-1` |
| 2. Сбор данных | прямые зависимости заданной версии пакета из реестра npm | `pract3-stage-2` |
| 3. Основные операции | граф с учётом транзитивности: BFS без рекурсии, фильтр, циклы, тестовый репозиторий | `pract3-stage-3` |
| 4. Дополнительные операции | обратные зависимости: какие пакеты зависят от заданного | `pract3-stage-4` |
| 5. Визуализация | описание графа на языке D2, картинка, ASCII-дерево, сравнение с npm | `pract3-stage-5` |

Данные запрашиваются по HTTP напрямую, без npm и сторонних библиотек:
`GET <repository>/<package>/<version>`. Прямые зависимости берутся
из поля `dependencies` ответа.

Граф строится обходом в ширину (BFS) без рекурсии. Очередь хранит
пакеты, которые ещё нужно разобрать, а множество `seen` — пакеты,
которые уже попали в очередь. Поэтому каждый пакет запрашивается
один раз, а циклические зависимости не зацикливают обход: ребро
цикла остаётся в графе, но пакет второй раз в очередь не попадает.

У зависимостей записаны требования к версии (`~1.3.8`, `^2.0.0`), а
реестр npm отдаёт пакет только по точной версии. Поэтому запрашивается
версия, записанная в требовании (`~1.3.8` → `1.3.8`), а если её нет
(`*`, `1.x`) — последняя версия `latest`.

## 2. Настройки

Настройки задаются в JSON-файле, по умолчанию `config.json`.
Все параметры, кроме `reverse`, обязательны.

| Параметр | Тип | Значение |
|---|---|---|
| `package` | строка | имя пакета: npm-имя, в тестовом режиме — большие латинские буквы |
| `repository` | строка | URL реестра npm, в тестовом режиме — путь к файлу |
| `test_mode` | true/false | режим работы с тестовым репозиторием |
| `version` | строка | точная версия пакета, например `4.18.2` |
| `ascii_tree` | true/false | дополнительно вывести зависимости в виде ASCII-дерева |
| `filter` | строка | подстрока для фильтрации пакетов, может быть пустой |
| `reverse` | true/false | необязательный, по умолчанию `false`: вывести обратные зависимости |

`filter` убирает из анализа пакеты, в имени которых есть эта подстрока,
а вместе с ними — пакеты, которые нужны только им. Пустая строка ничего
не убирает.

### Тестовый репозиторий

При `test_mode: true` параметр `repository` — путь к текстовому файлу с
описанием графа. Каждая строка — пакет и его прямые зависимости через
пробел, имена — большие латинские буквы. Пустые строки и строки с `#`
пропускаются. Версии в тестовом режиме не используются.

```
# Цикл A -> B -> C -> A и пакет D, который зависит сам от себя
A: B
B: C D
C: A
D: D
```

Ошибки файла: строка без двоеточия, имя не из больших латинских букв,
повторное описание пакета, отсутствие анализируемого пакета в файле.
Примеры лежат в `examples/repos`, конфигурации к ним — в `examples/configs`.

### Обратные зависимости

При `reverse: true` выводятся пакеты, которые зависят от заданного
напрямую или через другие пакеты. Граф тестового репозитория
переворачивается (`A: B` превращается в «от B зависит A»), и по нему
идёт тот же обход в ширину, что и на этапе 3, вместе с фильтром.
Режим работает только с тестовым репозиторием: чтобы найти всех, кто
зависит от пакета в реестре npm, пришлось бы перебрать все его пакеты.

### Визуализация

Граф выводится на языке диаграмм [D2](https://d2lang.com): анализируемый
пакет — отдельная фигура, каждая зависимость — стрелка
`"пакет" -> "зависимость"`. Описание сохраняется в `graph-<пакет>.d2`,
программа `d2` рисует по нему картинку `graph-<пакет>.svg`, и картинка
открывается на экране программой, которая в системе показывает SVG
(обычно браузер). В именах файлов `/` заменяется на `_`.

При `ascii_tree: true` после описания D2 выводится дерево зависимостей.
Пакет, который уже показан выше, второй раз не раскрывается и
помечается `(*)` — так дерево конечное даже при циклах (у `npm ls` то же
обозначается словом `deduped`).

## 3. Функции

`src/config.py`:

| Функция | Назначение |
|---|---|
| `load_config(path)` | читает файл и возвращает проверенные параметры |
| `validate(data)` | проверяет все параметры |
| `_read_json(path)` | читает JSON-документ из файла |
| `_get(data, key, kind)` | проверяет наличие и тип параметра |
| `_check_package(data, test_mode)` | проверяет имя пакета |
| `_check_repository(data, test_mode)` | проверяет URL или путь к файлу |
| `_check_version(data)` | проверяет формат версии |
| `_check_reverse(data, test_mode)` | проверяет необязательный режим обратных зависимостей |

`src/npm.py`:

| Функция | Назначение |
|---|---|
| `fetch_dependencies(repository, name, version)` | возвращает прямые зависимости пакета нужной версии |
| `pick_version(requirement)` | выбирает точную версию для запроса: `~1.3.8` → `1.3.8`, `*` → `latest` |
| `_fetch_json(url)` | загружает и разбирает JSON-документ по URL |

`src/graph.py`:

| Функция | Назначение |
|---|---|
| `build_graph(root, version, fetch, exclude)` | строит граф обходом в ширину без рекурсии, пропуская пакеты с подстрокой `exclude` |
| `invert(graph)` | переворачивает рёбра: для пакета — кто от него зависит |

`src/graph_file.py`:

| Функция | Назначение |
|---|---|
| `load_graph_file(path)` | читает файл тестового репозитория в словарь `{пакет: [зависимости]}` |
| `_parse_line(line, number)` | разбирает строку `A: B C` и проверяет имена |

`src/visual.py`:

| Функция | Назначение |
|---|---|
| `to_d2(graph, root)` | описывает граф на языке D2 |
| `show_image(d2_text, name)` | сохраняет описание, рисует SVG программой `d2` и открывает его |
| `ascii_tree(graph, root)` | рисует зависимости в виде ASCII-дерева |
| `_add_branches(graph, name, prefix, shown, lines)` | дописывает в дерево ветки одного пакета |

`src/main.py`:

| Функция | Назначение |
|---|---|
| `main(args)` | читает конфигурацию, показывает граф или обратные зависимости, возвращает код возврата |
| `load_graph(config)` | выбирает источник данных (реестр или тестовый файл) и строит граф |
| `load_reverse_graph(config)` | ищет обратные зависимости тем же обходом по перевёрнутому графу |
| `_dict_fetch(repository, package)` | готовит получение зависимостей из словаря-репозитория |
| `show_graph(config, graph)` | выводит описание D2, при `ascii_tree` — дерево, и открывает картинку |
| `print_reverse(config, graph)` | выводит, кто от кого зависит |

При любой ошибке приложение пишет сообщение в stderr и завершается с кодом 1.

## 4. Сборка и тесты

Сборка не нужна, достаточно установленного Python 3. Для картинки нужна
программа [d2](https://d2lang.com): в Linux и macOS она ставится командой
`curl -fsSL https://d2lang.com/install.sh | sh -s --`, для Windows есть
установщик на странице релизов. Без неё приложение выводит описание D2 и
дерево, а про картинку сообщает ошибку.

Команды выполняются из папки `pract3`:

```sh
./run.sh [файл]                     # запуск в Linux/macOS
run.bat [файл]                      # запуск в Windows
python3 -m unittest discover tests  # тесты
sh examples/demo_errors.sh          # демонстрация ошибок всех параметров
sh examples/demo_graph.sh           # граф на разных тестовых репозиториях
sh examples/demo_reverse.sh         # обратные зависимости
sh examples/demo_visual.sh          # визуализация трёх пакетов из npm
```

Если Python с python.org на macOS пишет `CERTIFICATE_VERIFY_FAILED`,
нужно один раз запустить `Install Certificates.command` из папки
`/Applications/Python 3.x`.

## 6. Сравнение со штатным инструментом npm

Штатный инструмент визуализации npm — `npm ls --all`: он выводит
дерево пакетов, установленных в проект. Для сравнения каждый пакет
ставился в пустую папку (npm 11.20.0):

```sh
npm init -y
npm install chalk@4.1.2
npm ls --all
```

Для `chalk` результат совпадает: те же 6 пакетов и та же структура.

```
└─┬ chalk@4.1.2
  ├─┬ ansi-styles@4.3.0
  │ └─┬ color-convert@2.0.1
  │   └── color-name@1.1.4
  └─┬ supports-color@7.2.0
    └── has-flag@4.0.0
```

| Пакет | Пакетов у инструмента | Пакетов у `npm ls` | Пакетов с другой версией |
|---|---|---|---|
| `chalk@4.1.2` | 6 | 6 | 2 |
| `body-parser@1.20.1` | 30 | 41 | 8 |
| `express@4.18.2` | 56 | 67 | 10 |

Почему есть расхождения:

1. **Выбор версии.** npm ставит самую новую версию, подходящую под
   требование, а инструмент запрашивает версию, записанную в требовании:
   для `^1.0.4` npm берёт `side-channel@1.1.1`, а инструмент —
   `side-channel@1.0.4`. В новой версии другие зависимости
   (`side-channel-list`, `side-channel-map`, `es-errors` и другие вместо
   `call-bind` и `has`), поэтому у `body-parser` и `express` различается
   часть дерева и число пакетов. У `chalk` версии тоже другие
   (`ansi-styles` 4.1.0 и 4.3.0), но зависимости у них одинаковые, и
   граф совпадает.
2. **Один узел на имя.** npm может поставить две версии одного пакета:
   в `express` есть `ms@2.0.0` для `debug` и `ms@2.1.3` для `send`.
   В графе инструмента у каждого имени один узел.
3. **Дерево и граф.** `npm ls` показывает дерево, где повторы помечены
   `deduped`, а описание D2 — граф, где каждый пакет нарисован один раз,
   а повторное использование видно по нескольким входящим стрелкам.
