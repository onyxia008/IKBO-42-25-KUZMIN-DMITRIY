# Граф зависимостей npm-пакета (вариант 17)

Учебный CLI-инструмент на Python 3 без сторонних библиотек.
Дисциплина «Конфигурационное управление», РТУ МИРЭА.

## 1. Общее описание

| Этап | Что реализовано | Тег |
|---|---|---|
| 1. Прототип | чтение параметров из JSON, вывод «ключ: значение», ошибки | `pract3-stage-1` |
| 2. Сбор данных | прямые зависимости заданной версии пакета из реестра npm | `pract3-stage-2` |
| 3. Основные операции | граф с учётом транзитивности: BFS без рекурсии, фильтр, циклы, тестовый репозиторий | `pract3-stage-3` |

Данные запрашиваются по HTTP напрямую, без npm и сторонних библиотек:
`GET <repository>/<package>/<version>`. Прямые зависимости берутся
из поля `dependencies` ответа.

Граф строится обходом в ширину (BFS) без рекурсии. Очередь хранит
пакеты, которые ещё нужно разобрать, а множество `seen` — пакеты,
которые уже попали в очередь. Поэтому каждый пакет запрашивается
один раз, а циклические зависимости не зацикливают обход: ребро
цикла остаётся в графе, но пакет второй раз в очередь не попадает.

У зависимостей записаны требования к версии (`~1.3.8`, `^2.0.0`), а
реестр npm отдаёт пакет только по точной версии. Поэтому запрашивается
версия, записанная в требовании (`~1.3.8` → `1.3.8`), а если её нет
(`*`, `1.x`) — последняя версия `latest`.

## 2. Настройки

Настройки задаются в JSON-файле, по умолчанию `config.json`.
Все параметры обязательны.

| Параметр | Тип | Значение |
|---|---|---|
| `package` | строка | имя пакета: npm-имя, в тестовом режиме — большие латинские буквы |
| `repository` | строка | URL реестра npm, в тестовом режиме — путь к файлу |
| `test_mode` | true/false | режим работы с тестовым репозиторием |
| `version` | строка | точная версия пакета, например `4.18.2` |
| `ascii_tree` | true/false | режим вывода зависимостей в виде ASCII-дерева |
| `filter` | строка | подстрока для фильтрации пакетов, может быть пустой |

`filter` убирает из анализа пакеты, в имени которых есть эта подстрока,
а вместе с ними — пакеты, которые нужны только им. Пустая строка ничего
не убирает. Параметр `ascii_tree` уже проверяется, но заработает на
этапе 5.

### Тестовый репозиторий

При `test_mode: true` параметр `repository` — путь к текстовому файлу с
описанием графа. Каждая строка — пакет и его прямые зависимости через
пробел, имена — большие латинские буквы. Пустые строки и строки с `#`
пропускаются. Версии в тестовом режиме не используются.

```
# Цикл A -> B -> C -> A и пакет D, который зависит сам от себя
A: B
B: C D
C: A
D: D
```

Ошибки файла: строка без двоеточия, имя не из больших латинских букв,
повторное описание пакета, отсутствие анализируемого пакета в файле.
Примеры лежат в `examples/repos`, конфигурации к ним — в `examples/configs`.

## 3. Функции

`src/config.py`:

| Функция | Назначение |
|---|---|
| `load_config(path)` | читает файл и возвращает проверенные параметры |
| `validate(data)` | проверяет все параметры |
| `_read_json(path)` | читает JSON-документ из файла |
| `_get(data, key, kind)` | проверяет наличие и тип параметра |
| `_check_package(data, test_mode)` | проверяет имя пакета |
| `_check_repository(data, test_mode)` | проверяет URL или путь к файлу |
| `_check_version(data)` | проверяет формат версии |

`src/npm.py`:

| Функция | Назначение |
|---|---|
| `fetch_dependencies(repository, name, version)` | возвращает прямые зависимости пакета нужной версии |
| `pick_version(requirement)` | выбирает точную версию для запроса: `~1.3.8` → `1.3.8`, `*` → `latest` |
| `_fetch_json(url)` | загружает и разбирает JSON-документ по URL |

`src/graph.py`:

| Функция | Назначение |
|---|---|
| `build_graph(root, version, fetch, exclude)` | строит граф обходом в ширину без рекурсии, пропуская пакеты с подстрокой `exclude` |

`src/graph_file.py`:

| Функция | Назначение |
|---|---|
| `load_graph_file(path)` | читает файл тестового репозитория в словарь `{пакет: [зависимости]}` |
| `_parse_line(line, number)` | разбирает строку `A: B C` и проверяет имена |

`src/main.py`:

| Функция | Назначение |
|---|---|
| `main(args)` | читает конфигурацию, строит и выводит граф, возвращает код возврата |
| `load_graph(config)` | выбирает источник данных (реестр или тестовый файл) и строит граф |
| `_test_fetch(config)` | готовит получение зависимостей из тестового репозитория |
| `print_graph(config, graph)` | выводит каждый пакет и его зависимости |

При любой ошибке приложение пишет сообщение в stderr и завершается с кодом 1.

## 4. Сборка и тесты

Сборка не нужна, достаточно установленного Python 3.
Команды выполняются из папки `pract3`:

```sh
./run.sh [файл]                     # запуск в Linux/macOS
run.bat [файл]                      # запуск в Windows
python3 -m unittest discover tests  # тесты
sh examples/demo_errors.sh          # демонстрация ошибок всех параметров
sh examples/demo_graph.sh           # граф на разных тестовых репозиториях
```

...

$ ./run.sh examples/configs/test_cycle.json

D -> D

$ ./run.sh examples/configs/test_filter.json
